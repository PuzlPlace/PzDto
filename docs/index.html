DTOs por herança, com cast automático e rastreamento

Estenda PzDto, declare propriedades tipadas e chame ::from($dados). O pacote converte cada valor para o tipo declarado, aninha DTOs e enums, e diz o que veio na entrada e o que mudou depois.

extends PzDto Cast automático #[PzDtoAttribute] / #[PzEnumAttribute] Entrada e saída previsíveis wasProvided / isDirty Eloquent sem acoplamento

O que é o PzDto?

Uma classe abstrata que transforma qualquer classe PHP em DTO (objeto de transferência de dados). Você declara as propriedades com tipos; o PzDto cuida de preencher, converter e serializar. Validação de negócio continua onde sempre esteve — FormRequest, Services e Entities; o DTO só garante que os dados chegam com o tipo certo.

Entrada flexível

from() aceita array, Eloquent Model, stdClass, outro DTO ou string JSON. Sempre devolve a classe chamada.

Cast pelo tipo

"12" vira int, "1,5" vira float, "2026-10-22" vira DateTime, "paid" vira enum.

Erros de conversão juntos

Se algo não converte ("abc" em int, enum inexistente), nada é instanciado e todos os campos problemáticos vêm numa só exceção.

Sabe o que veio

wasProvided() separa "não mandou" de "mandou null". isDirty() diz o que mudou. Perfeito para PATCH.

Instalação

O repositório é público, mas o pacote não está no Packagist. São dois passos.

1. Declare o repositório

No composer.json da aplicação, no mesmo nível de require:

"repositories": [
    { "type": "vcs", "url": "https://github.com/PuzlPlace/PzDto.git" }
]

2. Instale por versão

composer require puzl/pzdto:^1.0

Requisitos

  • PHP 8.1 ou superior. Nenhuma dependência obrigatória.
  • Com Laravel instalado, reconhece Eloquent Model, Collection e paginator automaticamente.
  • Não há Service Provider, config nem comando. Basta estender PzDto.
Opcional, mas recomendado: mensagens em português

No boot() do AppServiceProvider: PzDto::useLocale('pt_BR'); — as mensagens de erro de conversão (e das regras do bônus) saem em pt-BR. Se a API escolhe o idioma por requisição (header Accept-Language), use PzDto::useLocale(fn () => app()->getLocale());. Detalhes.

Início rápido

Um DTO de criação de pedido, com cliente aninhado, lista de itens e enum:

use Puzl\PzDto\PzDto;
use Puzl\PzDto\Attributes\PzDtoAttribute;

enum OrderStatus: string { case OPEN = 'open'; case PAID = 'paid'; }

final class CustomerDto extends PzDto
{
    public string $name;
    public ?string $email;
}

final class OrderItemDto extends PzDto
{
    public string $sku;
    public int $qty = 1;
    public float $price;
}

final class OrderCreateDto extends PzDto
{
    public string $description;
    public float $amount;

    public OrderStatus $status = OrderStatus::OPEN;   // enum pelo tipo, sem atributo
    public CustomerDto $customer;                     // DTO aninhado pelo tipo, sem atributo

    #[PzDtoAttribute(OrderItemDto::class)]              // array: aqui o atributo é obrigatório
    public array $items = [];

    public ?\DateTimeImmutable $due_at;
}

Regra simples: o tipo da propriedade manda. Enum, DTO e data são reconhecidos pelo tipo; #[PzDtoAttribute]/#[PzEnumAttribute] só são necessários em propriedade array (para dizer a classe dos itens). Em propriedade tipada eles são opcionais.

Usando:

$dto = OrderCreateDto::from([
    'description' => 'Pedido 123',
    'amount'      => '150,90',                 // string pt-BR → float 150.9
    'status'      => 'paid',                   // string → OrderStatus::PAID
    'customer'    => ['name' => 'Ana', 'email' => 'ana@x.com'],
    'items'       => [['sku' => 'A1', 'qty' => '2', 'price' => 10]],
    'due_at'      => '2026-11-01',             // string → DateTimeImmutable
]);

$dto->amount;              // 150.9 (float)
$dto->status;              // OrderStatus::PAID
$dto->customer->name;      // 'Ana'
$dto->items[0]->qty;       // 2 (int)
$dto->toArray();           // array pronto para JSON ou $model->fill()

Se algum valor não converte para o tipo declarado, nada é instanciado e todos os problemas vêm juntos:

try {
    OrderCreateDto::from(['amount' => 'abc', 'status' => 'x', 'items' => [['qty' => 'muitos']]]);
} catch (PzDtoValidationException $e) {
    $e->errors();
    // [
    //   'amount'      => ['The amount field must be a number.'],
    //   'status'      => ['The selected status is invalid.'],
    //   'items.0.qty' => ['The qty field must be an integer.'],
    // ]
}

Regras além do tipo (obrigatório, tamanho, e-mail…) ficam no FormRequest, no Service ou na Entity. Se precisar delas no próprio DTO, existe suporte opcional — veja o bônus no fim.

Fluxo típico: request → DTO → Model

Como o PzDto encaixa numa API Laravel. O FormRequest valida; o DTO garante os tipos e viaja até o service/repository.

Criação

// Controller
public function store(OrderStoreRequest $request, OrderService $service)
{
    $dto = OrderCreateDto::from($request->validated());

    return OrderResource::make($service->create($dto));
}

// Service
public function create(OrderCreateDto $dto): Order
{
    return DB::transaction(function () use ($dto) {
        $order = Order::create($dto->except('customer', 'items'));
        $order->items()->createMany($dto->only('items')['items']);

        return $order;
    });
}

Atualização parcial (PATCH)

Aqui o pulo do gato: toArrayProvided() devolve só o que veio na requisição. Campos não enviados não são tocados na Model.

final class OrderUpdateDto extends PzDto
{
    public string $description;
    public float $amount;

    public ?OrderStatus $status;

    public ?\DateTimeImmutable $due_at;
}

// PATCH /orders/1  { "status": "paid", "due_at": null }
$dto = OrderUpdateDto::from($request->validated());

$dto->wasProvided('status');   // true
$dto->wasProvided('due_at');   // true  (veio, mesmo sendo null)
$dto->wasProvided('amount');   // false (não veio)

$order->update($dto->toArrayProvided());
// UPDATE orders SET status = 'paid', due_at = NULL  — amount e description intactos
Nunca use toArray() para update parcial

toArray() traz todas as propriedades, com o "zero" do tipo nas que não vieram (0, '', null…). Num update() isso apaga colunas. Use toArrayProvided().

Leitura (Model → DTO → resposta)

$orders = Order::with('customer', 'items')->paginate();

$dtos = OrderViewDto::collect($orders);   // array de OrderViewDto, chaves preservadas

return response()->json(array_map(fn ($d) => $d->toArray(), $dtos));

Herança

Toda a lógica está em PzDto; não existe trait. Qualquer profundidade de herança funciona e from()/create() devolvem sempre a classe chamada (static).

// Base do projeto (opcional): um lugar para métodos comuns
abstract class BaseDto extends PzDto {}

class OrderCreateDto extends BaseDto
{
    public string $description;
    public int $company_id;
}

class OrderSpecialCreateDto extends OrderCreateDto
{
    public int $extra = 0;
    private string $secret = '';   // private também é preenchida
}

OrderSpecialCreateDto::from([...]);   // instância de OrderSpecialCreateDto
  • Propriedades do pai valem no filho, inclusive private (e os atributos declarados nele).
  • Filha pode redeclarar uma propriedade do pai (ex.: trocar o default). A declaração da filha vence.
  • public, protected, private e readonly são preenchidas. Só static é ignorada.
  • toArray() traz apenas as públicas, na ordem "pai antes da filha".
  • O construtor não é chamado pelo from(). Não dependa dele para inicializar estado.
  • Classe abstract não pode ser instanciada: BaseDto::from() lança PzDtoException.

Conversão de tipos

O tipo declarado da propriedade decide a conversão. Não precisa de atributo para escalares, datas e enums tipados.

final class FlagsDto extends PzDto
{
    public bool $active;
    public ?bool $notify;
}

FlagsDto::from(['active' => 'on'])->active;      // true  (checkbox marcado)
FlagsDto::from(['active' => '0'])->active;       // false
FlagsDto::from(['active' => 2])->active;         // true  (≠ 0)
FlagsDto::from(['active' => 'abc'])->active;     // false (texto desconhecido nunca é true)
FlagsDto::from([])->active;                       // false (não veio, não-nullable)
FlagsDto::from([])->notify;                       // null  (não veio, nullable)
Quer rejeitar "abc" em vez de virar false?

Valide no FormRequest ('active' => 'boolean') — ou, se o DTO for a única fronteira, use a regra do bônus #[PzIsBoolean], que só aceita true/false/0/1/"0"/"1"/"true"/"false".

Ausente × null × string vazia

Três situações diferentes, tratadas de forma previsível:

SituaçãoPropriedade nullable (?int)Não-nullable (int)
Chave não veiodefault da propriedade; senão nulldefault; senão o "zero" do tipo (0, 0.0, '', false, [], DTO vazio)
Veio nullnull (mesmo com default)default; senão o "zero"
Veio '' em número, data, enum ou DTOnull (formulário vazio = sem valor)default; senão o "zero"
Veio '' em string'' (string vazia é um valor legítimo)
Enum ou data sem valor em não-nullable—erro de validação ("is required"): não existe "zero" para eles
 
final class FilterDto extends PzDto
{
    public ?int $page;          // não veio → null
    public int $per_page = 15;  // não veio → 15; veio null → 15; veio "" → 15
    public ?int $min_qty;       // veio 0 → 0 (zero é valor!)
    public array $ids;          // não veio → []
}

$f = FilterDto::from(['min_qty' => 0, 'per_page' => '']);
$f->page;      // null
$f->per_page;  // 15
$f->min_qty;   // 0
$f->ids;       // []
Datas aceitam qualquer formato que o PHP entenda

"2026-10-22", "22/10/2026", "tomorrow"… tudo vira data. Para exigir um formato exato em input de API, mantenha a propriedade como string e use #[PzIsDateString], ou valide o formato no FormRequest.

DTOs e enums aninhados

Um DTO dentro de outro

Se a propriedade é tipada com uma classe PzDto, o aninhamento é automático. #[PzDtoAttribute] é opcional nesse caso (fica como documentação e para compatibilidade com a trait). O mesmo vale para enum: public OrderStatus $status converte sozinho.

final class OrderDto extends PzDto
{
    #[PzDtoAttribute]
    public CustomerDto $customer;     // pelo atributo

    public AddressDto $billing;       // pelo tipo, sem atributo — igual

    public ?AddressDto $shipping;     // nullable: não veio → null
}

$dto = OrderDto::from(['customer' => ['name' => 'Ana']]);
$dto->customer->name;   // 'Ana'
$dto->billing;          // AddressDto "vazio" (não-nullable, sem dados) — sem validar
$dto->shipping;         // null

Lista de DTOs

Em propriedade array, a classe é obrigatória no atributo. Cada item vira uma instância; as chaves do array recebido são preservadas.

#[PzDtoAttribute(OrderItemDto::class)]
public array $items = [];

// ou, com nome do parâmetro:
#[PzDtoAttribute(class: OrderItemDto::class)]
public array $items = [];

$dto = OrderDto::from(['items' => [['sku' => 'A'], ['sku' => 'B']]]);
$dto->items[1]->sku;   // 'B'

Enums

enum Status: int { case OPEN = 1; case PAID = 2; }
enum Size { case SMALL; case BIG; }          // enum puro também funciona

final class ProductDto extends PzDto
{
    public Status $status;               // pelo tipo

    #[PzEnumAttribute]
    public ?Status $previous;            // pelo atributo (opcional)

    #[PzEnumAttribute(Status::class)]
    public array $history = [];          // lista de enums: classe obrigatória

    public Size $size = Size::SMALL;
}

ProductDto::from(['status' => 2]);          // Status::PAID (pelo value)
ProductDto::from(['status' => '2']);        // Status::PAID (string numérica ok)
ProductDto::from(['status' => 'PAID']);     // Status::PAID (pelo name)
ProductDto::from(['status' => 99]);         // erro de validação: "The selected status is invalid."
ProductDto::from(['size' => 'BIG']);        // Size::BIG

Erros de aninhados usam notação de ponto

OrderDto::from(['customer' => ['name' => ['x']], 'items' => [['sku' => 'A'], ['qty' => 'x']]]);
// errors():
//   'customer.name' => ['The name field must be a string.']
//   'items.1.qty'   => ['The qty field must be an integer.']

// Input com formato errado também é erro de validação (nunca exceção de uso):
OrderDto::from(['customer' => 'abc', 'items' => [1, 2]]);
//   'customer' => ['The customer field must be an array.']
//   'items.0'  => ['The items field must be an array.'], 'items.1' => [...]
Instância pronta é mantida

Se o valor já é uma instância da classe esperada ('customer' => $customerDto, 'status' => Status::PAID), ela é usada como está, sem reconverter.

Entrada e saída

Formas de criar

Dto::from(mixed $values, ?array $destructuring = null): static

Aceita array, Eloquent Model, stdClass, objeto com toArray(), outro DTO ou string JSON. Converte e valida. null equivale a [].

Dto::create(?array $values): static

Mesma coisa que from(), só com array. Útil quando você já tem o array e quer o nome mais explícito.

Dto::collect(iterable $items): array

Lista de DTOs a partir de array, Collection, LazyCollection ou paginator. Erros de todos os itens juntos, com o índice no caminho ('3.qty').

Dto::fromTracked(mixed $values, ?array $destructuring = null): static

from() já com rastreamento de alterações ligado (ver).

Dto::blank(): static

Instância "vazia" sem validar (o que um aninhado não-nullable recebe quando a chave não vem).

OrderDto::from($request->validated());
OrderDto::from($order);                              // Eloquent Model
OrderDto::from('{"description":"x","amount":"10"}'); // JSON
OrderDto::from($outroDto);                           // copia as públicas (objetos preservados)
OrderDto::from((object) ['description' => 'x']);  // stdClass

Destructuring: achatar uma chave na raiz

O segundo argumento lista chaves cujo conteúdo é mesclado na raiz. Útil quando o payload vem com um envelope ou quando quer puxar uma relação da Model para o mesmo nível.

// payload: { "name": "Ana", "address": { "city": "SP", "zip": "01001-000" } }
final class CustomerFlatDto extends PzDto
{
    public string $name;
    public string $city;
    public string $zip;
}

$dto = CustomerFlatDto::from($payload, ['address']);
$dto->city;   // 'SP'

Formas de sair

$dto->toArray(): array

Todas as públicas. Enum backed → value; enum puro → name; DTO aninhado → array; data → "Y-m-d H:i:s" no fuso do objeto.

$dto->toJson(int $flags = 0): string  ·  json_encode($dto)

Mesmo conteúdo do toArray(). toJson() preserva 10.0 como float.

$dto->only(string ...$paths): array  ·  $dto->except(string ...$paths): array

toArray() parcial, com notação de ponto e * em qualquer profundidade.

$dto->toArrayProvided(): array

Só o que veio na entrada, em todos os níveis (PATCH).

$dto->toArray();
// ['description' => 'Pedido', 'amount' => 150.9, 'status' => 'paid',
//  'customer' => ['name' => 'Ana', 'email' => 'ana@x.com'],
//  'items' => [['sku' => 'A1', 'qty' => 2, 'price' => 10.0]],
//  'due_at' => '2026-11-01 00:00:00']

$dto->only('description', 'items.*.sku');
// ['description' => 'Pedido', 'items' => [['sku' => 'A1']]]

$dto->except('customer', 'items.*.price');
// tudo menos customer, e itens sem price

Campos nunca preenchidos

toArray() sempre traz todas as públicas. Se você criou com new e preencheu só parte, as demais saem com o que o create() daria sem a chave: default; null se nullable; senão o "zero" do tipo. Enum/data sem default saem null.

$dto = new OrderDto();
$dto->description = 'x';

$dto->toArray();
// ['description' => 'x', 'amount' => 0.0, 'status' => 'open', 'customer' => ['name' => '', 'email' => null], 'items' => [], 'due_at' => null]

O que veio e o que mudou

Dois rastreamentos independentes, no espírito do Request e do isDirty() do Eloquent.

1. O que veio na entrada — sempre ligado

Cada propriedade lembra se a chave estava presente no from()/create()/fill(). Isso separa "não mandou" de "mandou null".

MétodoO que responde
wasProvided('a', 'b.c', 'items.*.sku')Todas as chaves vieram? (*: lista não vazia e todos os itens têm a chave)
wasProvidedAny(...)Alguma veio?
missing(...)Alguma não veio?
filled(...)Veio e está preenchida (não null, não ''/espaços, não [])
anyFilled(...) / isNotFilled(...)Alguma preenchida? / Nenhuma preenchida?
provided()Nomes das propriedades (1º nível) que vieram
get('items.0.sku', $default)Valor pelo caminho (real: DTO, enum, DateTime). 'items.*.sku' devolve lista
whenProvided('x', fn ($v, $dto) => …, fn ($dto) => …)Executa o callback se veio; senão o default. Encadeável
whenFilled(...)Idem, se preenchida
fill([...])Atribui convertendo e validando (tudo ou nada) e marca como recebido
fillMissing([...])fill() só das que ainda não vieram (defaults de negócio)
toArrayProvided()Array só com o que veio, em todos os níveis
 
$dto = OrderUpdateDto::from(['description' => 'Novo', 'due_at' => null]);

$dto->wasProvided('description');      // true
$dto->wasProvided('due_at');           // true  — veio null
$dto->filled('due_at');                // false — veio, mas vazio
$dto->missing('amount');               // true
$dto->provided();                      // ['description', 'due_at']

$dto->whenProvided('due_at', fn ($date) => $this->reschedule($order, $date))
    ->whenFilled('description', fn ($text) => $this->log($text));

$dto->fillMissing(['status' => 'open']);  // aplica só se status não veio
$dto->toArrayProvided();                   // ['description' => 'Novo', 'due_at' => null, 'status' => 'open']
Caminhos: regras rápidas

O primeiro segmento precisa ser propriedade pública — erro de digitação lança PzDtoException na hora. Dentro dele, caminho inexistente só devolve false/$default. Funciona em DTO aninhado, lista de DTO e array comum.

2. O que mudou depois — opt-in (dirty)

Guarda um snapshot e compara. Desligado por padrão porque custa memória em listas grandes. Três formas de ligar:

// a) na instância
$dto = OrderUpdateDto::from($dados)->trackChanges();

// b) na criação
$dto = OrderUpdateDto::fromTracked($dados);

// c) na classe: todo from()/create() dela (e das filhas) já nasce rastreando
#[PzTrackChanges]
final class OrderUpdateDto extends PzDto { ... }
MétodoO que responde
isDirty() / isDirty('a', 'b')Algo mudou? / Algum desses mudou? Filho alterado suja o pai
isClean(...)O inverso
getDirty()['campo' => valorAtual] (1º nível)
getDirtyPaths()Em notação de ponto, já serializado, descendo em aninhados: ['items.1.qty' => 3]
getOriginal('campo') / getOriginal()Valor antes das mudanças (um ou todos)
syncOriginal()O estado atual vira o original
isTrackingChanges()Está ligado?
 
$dto = OrderDto::fromTracked(['amount' => 10, 'customer' => ['name' => 'Ana']]);

$dto->isDirty();                   // false

$dto->amount = 15;
$dto->customer->name = 'Bia';

$dto->isDirty('amount');           // true
$dto->isDirty('customer');         // true — o filho mudou
$dto->getDirty();                  // ['amount' => 15.0, 'customer' => CustomerDto]
$dto->getDirtyPaths();             // ['amount' => 15.0, 'customer.name' => 'Bia']
$dto->getOriginal('amount');       // 10.0
$dto->customer->getOriginal('name'); // 'Ana'

$dto->amount = 10;
$dto->isDirty('amount');           // false — voltou ao original

$dto->syncOriginal();              // zera o dirty
Limites que vale saber
  • getOriginal('customer') devolve a mesma instância do filho (snapshot raso). Para o valor antigo de dentro, pergunte ao filho: $dto->customer->getOriginal('name'), ou use getDirtyPaths().
  • DateTime mutável alterado no lugar (->modify()) não é detectado. Prefira DateTimeImmutable.
  • #[PzTrackChanges] não vale para new (o construtor não é interceptado): chame ->trackChanges().
  • clone $dto é profundo: filhos e snapshot são copiados; mexer no clone não suja o original.

Laravel / Eloquent

O pacote não depende do Laravel, mas reconhece Model, Collection e paginator quando estão presentes.

Model → DTO

Dto::from($model) lê a Model campo a campo (getAttribute()), e não pelo $model->toArray(). Na prática:

  • Casts aplicados: decimal, boolean, array, enum, datetime.
  • Datas como Carbon no fuso da aplicação (o toArray() da Model converteria para ISO em UTC).
  • $hidden disponível, $appends e accessors (getFooAttribute, Attribute::make) mesmo fora de $appends.
  • Relações só se já carregadas — nunca dispara lazy loading. order_items no DTO encontra a relação orderItems.
  • Propriedade string recebendo data vem formatada: Y-m-d H:i:s, Y-m-d (cast date) ou o formato do cast (date:d/m/Y).
  • Só os campos que o DTO declara são lidos.
final class OrderViewDto extends PzDto
{
    public int $id;
    public float $amount;                // cast decimal:2 → "10.50" → 10.5
    public OrderStatus $status;          // cast enum
    public \DateTimeInterface $paid_at;  // Carbon, America/Sao_Paulo
    public string $created_at;           // "2026-10-22 09:30:00"

    #[PzDtoAttribute]
    public ?CustomerDto $customer;       // relação carregada → DTO; não carregada → null

    #[PzDtoAttribute(OrderItemDto::class)]
    public array $order_items = [];      // relação orderItems
}

$order = Order::with('customer', 'orderItems')->find(1);

DTO → Model

Datas saem como Y-m-d H:i:s e enums como value, prontos para fill():

// criar
$order = Order::create($dto->except('items', 'customer'));

// atualizar parcialmente — só o que veio na requisição
$order->update($dto->toArrayProvided());

// atualizar campos escolhidos
$order->fill($dto->only('amount', 'status', 'paid_at'))->save();

Migrando da FromArrayTrait

A migração é gradual, DTO a DTO. Os dois convivem e o aninhamento cruzado funciona nos dois sentidos (PzDto com filho legado e vice-versa).

  1. Troque use FromArrayTrait; por extends PzDto (ou por uma base nova que estenda PzDto).
  2. Troque os imports: App\Helpers\DtoAttribute → Puzl\PzDto\Attributes\PzDtoAttribute (idem EnumAttribute). Durante a transição os atributos antigos também são reconhecidos pelo nome curto.
  3. Revise as diferenças de comportamento — a maioria são correções de bugs que o código pode estar contornando.
  4. Rode os testes do módulo.

Antes

use App\Helpers\FromArrayTrait;
use App\Helpers\DtoAttribute;

class OrderCreateDto
{
    use FromArrayTrait;

    #[PzDtoAttribute(namespace: ItemDto::class)]
    public array $items;
}

Depois

use Puzl\PzDto\PzDto;
use Puzl\PzDto\Attributes\PzDtoAttribute;

class OrderCreateDto extends PzDto
{
    #[PzDtoAttribute(ItemDto::class)]
    public array $items = [];
}
Não faça BaseDto extends PzDto enquanto houver filhos com a trait

As assinaturas de from()/toArray() conflitam. Crie uma base nova (BaseDtoV2) durante a transição e unifique no fim.

Perguntas frequentes

Preciso registrar algum Service Provider?

Não. Nada de config nem comando; basta estender PzDto. Se quiser mensagens em português, uma linha no boot(): PzDto::useLocale('pt_BR').

Posso usar new MeuDto() e preencher na mão?

Pode. Só lembre: nada foi "recebido" (provided() vazio), o rastreamento não liga sozinho e toArray() completa os campos vazios com o zero do tipo. fill([...]) converte, valida e marca como recebido.

Como copio um DTO?

clone $dto (profundo) ou MeuDto::from($dto) (revalida e marca tudo como recebido). Para preservar o "o que veio": MeuDto::from($dto->toArrayProvided()).

Posso ter propriedades que não vêm do input (ex.: user_id do token)?

Sim. Declare normalmente e preencha depois com $dto->fill(['user_id' => auth()->id()]) — ou passe junto no array do from(). Propriedades protected entram no from() mas não saem no toArray().

É lento por usar reflexão?

A reflexão de cada classe (propriedades, tipos, atributos, regras) é lida uma vez e fica em cache estático. Referência: 10 mil DTOs com 30 campos, um aninhado e uma lista de 3 itens em ~180 ms. O rastreamento de alterações é opt-in justamente para listas grandes não pagarem por ele.

Como rodo os testes do pacote?

composer test

Duas suítes: Unit (tests/Unit) e Features (tests/Features — Eloquent e convivência com a FromArrayTrait).

Bônus: validação por atributo

Leia antes de usar

A função deste pacote é ser DTO: tipar e transportar dados. Validação de negócio a gente prioriza no FormRequest (entrada HTTP), nos Services e nas Entities. Os atributos abaixo existem para os casos em que o DTO é a única fronteira (fila, integração, import, CLI) ou para quem está migrando DTOs que já validavam. Não duplique no DTO uma regra que o FormRequest já cobre.

Como funciona: atributos de Puzl\PzDto\Attributes\Validation na propriedade; rodam depois do cast, dentro do mesmo from(); os erros saem junto com os de conversão na PzDtoValidationException.

use Puzl\PzDto\Attributes\Validation\{PzRequired, PzLength, PzIsEmail};

final class ImportCustomerDto extends PzDto
{
    #[PzRequired, PzLength(max: 120)]
    public string $name;

    #[PzIsEmail]
    public ?string $email;
}

Regras disponíveis

Namespace Puzl\PzDto\Attributes\Validation. Todas aceitam message: para texto próprio (placeholders :field, :min, :max, :values…). Podem ser combinadas na mesma propriedade, em qualquer ordem.

RegraPassa quandoExemplo
PzRequiredVeio e não é null, ''/espaços ou []#[PzRequired]
PzRequiredIfComo PzRequired, só quando outro campo tem o valor#[PzRequiredIf('type', 'company')]
PzRequiredWithComo PzRequired, só quando algum dos outros veio#[PzRequiredWith('street', 'city')]
PzIsNotEmptyNão é vazio no sentido do empty() (0 e '0' falham)#[PzIsNotEmpty]
PzIsString / PzIsInt / PzIsFloat / PzIsBooleanO valor bruto tem o formato: "5" passa em PzIsInt, "5.5" não; "1,5" passa em PzIsFloat#[PzIsInt]
PzMin(n) / PzMax(n)Número: valor; string: nº de caracteres; array: nº de itens#[PzMin(0)], #[PzMax(10)]
PzLength(min, max)Caracteres (multibyte) de uma string#[PzLength(min: 3, max: 120)]
PzMatches(regex)preg_match casa#[PzMatches('/^\d{5}-\d{3}$/')]
PzIn([...])Está na lista (enum compara pelo value/name; array: todos os itens)#[PzIn(['a', 'b'])], #[PzIn([Status::OPEN])]
PzIsEmail / PzIsUrl / PzIsUUIDfilter_var / UUID v1–8, nil e max#[PzIsEmail]
PzHasExtension([...])Nome de arquivo com extensão permitida (vazio = qualquer, mas precisa ter)#[PzHasExtension(['pdf', 'xml'])]
PzIsDateString(format, min, max)String no formato DATE (padrão), DATETIME, ISO8601 ou FLEXIBLE, dentro dos limites#[PzIsDateString(min: '2020-01-01')]

Quando cada regra ignora o valor

  • Só PzRequired* e PzIsNotEmpty cobram presença. As demais ignoram null (e a maioria ignora ''): para "obrigatório e e-mail", combine #[PzRequired, PzIsEmail].
  • PzLength, PzMatches, PzIsEmail… ignoram valor que não é string. PzMin/PzMax ignoram o que não é número, string nem array.
  • A validação roda depois do cast: PzMin(18) em int $age vê 20 mesmo que tenha vindo "20". As regras Is* olham o valor bruto de propósito.
final class SignupDto extends PzDto
{
    #[PzRequired, PzLength(min: 3, max: 80)]
    public string $name;

    #[PzRequired, PzIsEmail]
    public string $email;

    #[PzIsInt, PzMin(18), PzMax(120)]
    public int $age;

    #[PzIn(['person', 'company'])]
    public string $type = 'person';

    #[PzRequiredIf('type', 'company'), PzMatches('/^\d{14}$/', message: 'CNPJ de :field inválido')]
    public ?string $ein;

    #[PzMax(5), PzLength(max: 20)]   // PzMax(5) conta os itens do array; PzLength ignora (não é string)
    public array $tags = [];
}

Revalidar depois de alterar

$dto = SignupDto::from($dados);
$dto->age = 5;
$dto->assertValid();   // PzDtoValidationException: age must be at least 18

Mensagens e idioma

Por padrão as mensagens saem em inglês, no mesmo estilo do Laravel. Três níveis de personalização, do mais simples ao mais fino:

1. Idioma global

// AppServiceProvider::boot()
PzDto::useLocale('pt_BR');

// agora:
// 'O campo name é obrigatório.'
// 'O campo age deve ser no mínimo 18.'
// 'O valor selecionado para status é inválido.'

1b. Idioma por requisição (middleware / Accept-Language)

Passe um callable: ele é consultado na hora de montar cada mensagem, então segue o que o middleware definiu, sem depender de ordem de execução. Idioma desconhecido cai em inglês; pt-BR, pt_br e pt são aceitos.

// AppServiceProvider::boot() — uma vez
PzDto::useLocale(fn () => app()->getLocale());

// Middleware SetLocale — por requisição
public function handle(Request $request, Closure $next)
{
    app()->setLocale($request->getPreferredLanguage(['pt_BR', 'en']) ?? 'pt_BR');

    return $next($request);
}

// Accept-Language: en     → 'The name field is required.'
// Accept-Language: pt-BR  → 'O campo name é obrigatório.'
Octane / workers

Como o estado é estático e o processo sobrevive entre requisições, a forma com callable é a segura: o idioma é lido na hora, nunca fica "preso" na requisição anterior.

2. Sobrescrever textos por chave

Vale por cima do idioma ativo. As chaves estão em Puzl\PzDto\Support\Messages::LOCALES: required, integer, numeric, boolean, string, array, date, enum, in, email, url, uuid, regex, extension, length.min, length.max, min.numeric, min.string, min.array, max.*, required_if, required_with…

PzDto::useMessages([
    'required'    => 'Informe :field.',
    'min.numeric' => ':field precisa ser pelo menos :min.',
]);

3. Mensagem no atributo (+ tradutor)

#[PzLength(min: 3, max: 5, message: 'Código :field precisa de :min a :max caracteres')]
public string $code;

// Para passar o texto do atributo pelo trans() do Laravel:
PzDto::translateMessagesUsing(fn (string $key, array $replace) => trans($key, $replace));

#[PzRequired(message: 'validation.custom.code.required')]
public string $code;
O nome do campo aparece cru

:field é o nome da propriedade (due_at). Se quiser "data de vencimento", use message: na regra ou trate no handler da aplicação.

Regra customizada

Regra simples

Implemente ValidationRule numa classe marcada como atributo. Recebe o valor convertido, o bruto e o nome do campo; devolve a mensagem de erro ou null.

use Puzl\PzDto\Contracts\ValidationRule;
use Puzl\PzDto\Support\Messages;

#[\Attribute(\Attribute::TARGET_PROPERTY)]
final class Cpf implements ValidationRule
{
    public function __construct(public readonly ?string $message = null) {}

    public function validate(mixed $value, mixed $raw, string $field): ?string
    {
        if ($value === null || $value === '') {
            return null;   // deixe o PzRequired cuidar de presença
        }

        return CpfValidator::isValid((string) $value)
            ? null
            : ($this->message ?? "O campo {$field} não é um CPF válido.");
    }
}

// uso
#[PzRequired, Cpf]
public string $document;

Regra que olha outros campos

Implemente ContextualValidationRule: mesma assinatura, mais o array com o input do mesmo nível.

use Puzl\PzDto\Contracts\ContextualValidationRule;

#[\Attribute(\Attribute::TARGET_PROPERTY)]
final class AfterField implements ContextualValidationRule
{
    public function __construct(public readonly string $other) {}

    public function validate(mixed $value, mixed $raw, string $field, array $input): ?string
    {
        $start = $input[$this->other] ?? null;
        if ($value === null || $start === null) {
            return null;
        }

        return new \DateTimeImmutable((string) $value) > new \DateTimeImmutable((string) $start)
            ? null
            : "O campo {$field} deve ser posterior a {$this->other}.";
    }
}

final class PeriodDto extends PzDto
{
    #[PzRequired]
    public string $starts_at;

    #[PzRequired, AfterField('starts_at')]
    public string $ends_at;
}

No from(), $input é o array bruto recebido. No assertValid() e no fill(), é o estado atual do DTO (mais o que está chegando).
