DTOs por herança, com cast e validação

PzDto é a classe base dos DTOs da Puzl: class FinanceCreateDto extends PzDto e pronto — sem use de trait. Converte tipos automaticamente, aninha DTOs e enums com #[DtoAttribute]/#[EnumAttribute] e valida com atributos. É o sucessor da FromArrayTrait.

extends PzDto Cast automático DtoAttribute / EnumAttribute Validação por atributo Convive com a FromArrayTrait

O que é o PzDto?

Uma classe abstrata que transforma qualquer classe PHP em DTO. Chame Dto::from($dados) com array, Model, stdClass, outro DTO ou JSON e receba a instância preenchida, com cada propriedade convertida para o tipo declarado.

Herança

X extends PzDto ou X extends BaseDto extends PzDto: from() sempre devolve a classe chamada.

Mesma declaração

#[DtoAttribute] e #[EnumAttribute] funcionam como na trait — em qualquer ordem, junto com outros atributos.

Validação

#[Required], #[Length], #[IsEmail]… todos os erros juntos numa exceção.

Sem Laravel obrigatório

Só PHP 8.1. Aceita Model/Collection por toArray().

Instalação

O repositório PuzlPlace/PzDto é público, mas o pacote não está no Packagist — é distribuído pelo próprio repositório Git. Adicione o repositório ao composer.json do projeto consumidor:

{
    "repositories": [
        {
            "type": "vcs",
            "url": "https://github.com/PuzlPlace/PzDto.git"
        }
    ]
}

Em seguida, instale via Composer:

composer require puzl/pzdto:^1.0

Cada release é uma tag semver (veja as Releases). Use ^1.0 para receber correções e recursos novos sem nunca subir de major; evite dev-production, que segue o topo da branch sem versão.

Início rápido

use Puzl\PzDto\PzDto;
use Puzl\PzDto\Attributes\DtoAttribute;
use Puzl\PzDto\Attributes\EnumAttribute;
use Puzl\PzDto\Attributes\Validation\{Required, Length, Min};

class FinanceCreateDto extends PzDto
{
    #[Required, Length(max: 120)]
    public string $description;

    #[Min(0)]
    public float $amount;

    #[EnumAttribute]
    public FinanceTypeEnum $type;

    #[DtoAttribute(FinanceInstallmentDto::class)]
    public array $installments = [];
}

$dto = FinanceCreateDto::from($request->validated());

Herança

Toda a lógica está na classe PzDto; não existe trait. Qualquer nível de herança funciona e from()/create() retornam static:

abstract class BaseDto extends PzDto {}

class FinanceCreateDto extends BaseDto { ... }

FinanceCreateDto::from([...]); // instância de FinanceCreateDto
  • Propriedades do pai (inclusive private) e da filha são preenchidas; a filha pode redeclarar uma propriedade.
  • readonly, protected e private são suportadas. Propriedades static são ignoradas.
  • O construtor da classe não é chamado.
  • Validações declaradas no pai valem para as filhas.

DTOs e enums aninhados

class OrderDto extends PzDto
{
    #[DtoAttribute]                       // pelo tipo da propriedade
    public CustomerDto $customer;

    #[DtoAttribute(ItemDto::class)]       // lista: classe obrigatória
    public array $items = [];

    #[EnumAttribute]
    public ?StatusEnum $status;

    #[EnumAttribute(StatusEnum::class)]
    public array $history = [];

    public StatusEnum $kind = StatusEnum::OPEN; // enum/DTO pelo tipo também funciona sem atributo
}

Os atributos podem vir em qualquer ordem e combinados com validações (#[IsNotEmpty, EnumAttribute], #[Max(10)] #[DtoAttribute(ItemDto::class)]). Enum com valor que não existe gera erro — não cai mais no primeiro case.

A classe do #[DtoAttribute] pode ser um DTO legado com FromArrayTrait: basta ter static from().

Entrada e saída

Dto::from(['a' => 1]);
Dto::from($model);                  // Eloquent: campo a campo (ver Laravel / Eloquent)
Dto::collect($models);              // lista de DTOs
Dto::from((object) ['a' => 1]);
Dto::from($outroDto);               // propriedades públicas, preservando objetos
Dto::from('{"a":1}');             // JSON inválido lança PzDtoException
Dto::from($dados, ['address']);    // mescla $dados['address'] na raiz
Dto::create(['a' => 1]);

$dto->toArray();                    // enum → value, data → "Y-m-d H:i:s"
$dto->toJson();                     // = json_encode($dto)
$dto->assertValid();                // revalida após alterar propriedades

Campos não preenchidos no toArray()

toArray(), toJson() e json_encode($dto) trazem sempre todas as propriedades públicas, na ordem de declaração (pai antes da filha). Um campo que nunca recebeu valor — por exemplo depois de new com atribuição parcial — sai com o que o create() daria se a chave não viesse:

Campo não preenchidoNo toArray()
com defaulto default

não-nullable (float, int, string, bool, array)0.0, 0, '', false, []
enum ou data não-nullablenull (não têm zero)

$dto = new FinanceDto();
$dto->description = 'Aluguel';
$dto->toArray(); // ['description' => 'Aluguel', 'amount' => 0.0, 'discount' => null, ...]

Atribuição manual não converte nem valida; use assertValid() ou prefira Dto::create([...]).

Rastreamento (dirty)

Inspirado no isDirty() do Eloquent, em três grupos.

O que veio na entrada (sempre ligado)

Separa "não mandou" de "mandou null" — ideal para update parcial (PATCH):

$dto = FinanceUpdateDto::from(['description' => 'Aluguel', 'discount' => null]);

$dto->wasProvided('discount');     // true  (veio null)
$dto->wasProvided('amount');       // false (não veio)
$dto->provided();                 // ['description', 'discount']
$dto->toArrayProvided();          // ['description' => 'Aluguel', 'discount' => null]

$repository->update($id, $dto->toArrayProvided()); // não sobrescreve o resto

Recortes e caminhos

only() e except() aceitam notação de ponto e * em qualquer profundidade, misturando DTO, lista de DTO e array comum:

$dto->only('description', 'items.*.sku', 'items.*.tag.name');
// ['description' => 'Pedido', 'items' => [['sku' => 'A', 'tag' => ['name' => 'novo']], ...]]

$dto->only('items.1.qty');              // ['items' => [1 => ['qty' => 2]]]
$dto->except('items.*.qty', 'customer.document');
  • O primeiro segmento precisa ser propriedade pública: erro de digitação lança PzDtoException.
  • Dentro dele, caminho inexistente é ignorado; lista percorrida por * mantém os índices.
  • O resultado segue a ordem das propriedades, não a ordem dos caminhos pedidos.

toArrayProvided() também desce nos aninhados: cada DTO (direto ou em lista) entrega só os campos que vieram para ele — PATCH aninhado não sobrescreve o que não foi enviado.

O que mudou (opt-in)

Desligado por padrão. Três formas de ligar:

FormaQuando usar
$dto->trackChanges()numa instância qualquer, inclusive criada com new
X::fromTracked($dados)na criação; mesmos parâmetros do from()
#[TrackChanges] na classeDTO que sempre precisa do dirty: todo from()/create() dele e das filhas já nasce rastreando (não vale para new)
 
use Puzl\PzDto\Attributes\TrackChanges;

#[TrackChanges]
class FinanceUpdateDto extends PzDto { ... }

FinanceUpdateDto::from($dados)->isDirty();      // false, já rastreando
OutroDto::fromTracked($dados)->isDirty();       // false, já rastreando

Uso:

$dto = FinanceUpdateDto::from($dados)->trackChanges();

$dto->amount = 15;
$dto->isDirty();                  // true
$dto->isDirty('description');     // false
$dto->isClean('description');     // true
$dto->getDirty();                 // ['amount' => 15.0]
$dto->getOriginal('amount');      // 10.0
$dto->getDirtyPaths();            // ['amount' => 15.0, 'items.1.qty' => 3] — desce nos aninhados
$dto->syncOriginal();             // estado atual vira o original
  • DTO aninhado alterado ($dto->address->city = 'RJ') suja o campo do pai, inclusive em listas.
  • DTO aninhado trocado por outra instância é comparado pelo conteúdo; enums por case; datas pelo instante e fuso.
  • Voltar ao valor original deixa o campo limpo.
  • Sem rastreamento ligado, isDirty()/isClean()/getDirty()/getOriginal() lançam PzDtoException; isTrackingChanges() diz se está ligado.
Por que opt-in?
Guardar o original de cada instância praticamente dobra a memória de listas grandes (benchmark: 10 mil DTOs com 30 campos e aninhados, 17,5 → 32,9 MB). O provided custa ~4% no from() e fica sempre ligado. Rode composer bench para medir.
DateTime mutável
A cópia do original é rasa: $dto->date->modify('+1 day') em DateTime mutável não é detectado. Use DateTimeImmutable (ou atribua uma nova instância).

Laravel / Eloquent

O pacote não depende do Laravel, mas reconhece Eloquent Model, Collection e paginator quando estão instalados.

Model → DTO

$dto = OrderDto::from($order);                 // uma Model
$dtos = OrderDto::collect(Order::with('items')->get()); // Collection, paginator ou array

O from() lê a Model campo a campo com getAttribute(), e não via $model->toArray():

Na ModelNo DTO
datetime, date, timestampsCarbon no fuso da aplicação. O toArray() da Model entregaria string ISO em UTC (3h a mais em America/Sao_Paulo).
data em prop stringY-m-d H:i:s; Y-m-d no cast date; o formato do cast em date:d/m/Y
boolean, integer, float, decimal:2, array, object, enumconvertidos para o tipo da prop
$hiddendisponível (o DTO declara o campo explicitamente)
$appendslido pelo accessor
relação carregadaDTO ou lista de DTOs; order_items encontra orderItems
relação não carregadaausente — nunca dispara lazy loading; wasProvided() = false

Só os campos que o DTO declara são lidos. collect() preserva as chaves e junta os erros de todos os itens com o índice no caminho (1.name).

DTO → Model

Datas saem do toArray() como Y-m-d H:i:s, prontas para os casts da Model.

// criar
Order::create($dto->toArray());

// atualizar: só o que veio na requisição
$order->update($dto->toArrayProvided());

// ou: só o que mudou desde o from()
$dto = OrderDto::fromTracked($order);
// ... altera o DTO ...
$order->update($dto->only(...array_keys($dto->getDirty()))); // only() serializa datas/enums/DTOs
Nunca toArray() em update
toArray() traz todas as propriedades (as não preenchidas com default/zero/null) e sobrescreveria colunas que não vieram. Em update use toArrayProvided().

Regras disponíveis

Namespace Puzl\PzDto\Attributes\Validation. Todas aceitam message:. As regras rodam depois da conversão e ignoram null (exceto Required e IsNotEmpty).

Erros

Conversões que falham e regras violadas são reunidas e lançadas numa única PzDtoValidationException (extends InvalidArgumentException):

try {
    OrderDto::from($dados);
} catch (PzDtoValidationException $e) {
    $e->errors();   // ['customer.name' => ['The name field is required.'], 'items.1.qty' => [...]]
    $e->dtoClass(); // OrderDto::class
}

Placeholders nas mensagens: :field, :min, :max, :values. Para traduzir mensagens customizadas (ex.: chaves de lang/), registre no AppServiceProvider:

PzDto::translateMessagesUsing(fn (string $key, array $replace) => trans($key, $replace));

Erros de declaração (ex.: #[DtoAttribute] em array sem classe) lançam PzDtoException.

Regra customizada

#[\Attribute(\Attribute::TARGET_PROPERTY)]
final class Cpf implements \Puzl\PzDto\Contracts\ValidationRule
{
    public function validate(mixed $value, mixed $raw, string $field): ?string
    {
        return CpfValidator::isValid($value) ? null : "CPF inválido em $field";
    }
}

Migrando da FromArrayTrait

PzDto e FromArrayTrait convivem no mesmo projeto: a migração é gradual, DTO a DTO.

  1. Troque extends BaseDto + use FromArrayTrait; por extends PzDto (ou por uma base nova do projeto que estenda PzDto).
  2. Troque os imports App\Helpers\DtoAttribute/EnumAttribute por Puzl\PzDto\Attributes\... (se esquecer, os antigos continuam reconhecidos pelo nome).
  3. Revise as diferenças de comportamento no DTO migrado.

Aninhamento cruzado funciona nos dois sentidos: um PzDto pode ter #[DtoAttribute(DtoLegado::class)] e um DTO legado pode ter uma propriedade do tipo de um PzDto.

BaseDto durante a transição
Não faça BaseDto extends PzDto enquanto houver DTOs com use FromArrayTrait herdando dele — as assinaturas conflitam. Use uma base nova para os DTOs migrados e, quando o último legado sair, aponte BaseDto para PzDto.

Perguntas frequentes

Preciso registrar algum Service Provider?

Não. O pacote não tem config nem comando; basta estender PzDto.

É lento por usar reflexão?

A reflexão de cada classe (propriedades, tipos, atributos e regras) é lida uma vez e fica em cache estático — from() em listas grandes não refaz esse trabalho.

Como rodo os testes do pacote?

composer test

Duas suítes: Unit (tests/Unit) e Features (tests/Features — convivência com a FromArrayTrait e reprodução dos bugs antigos).
